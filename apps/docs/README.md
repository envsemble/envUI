# Documentation application

This React application consumes only public envUI exports. Ordinary examples use per-icon `@envsemble/envui/icons/Name` imports. The offline Icons & assets catalogue intentionally imports the full public icon barrel, renders 72 results per page, and supplies exact per-icon imports for products. A compact icon grid puts the symbol above its label, with common icons first and an outline/filled switch. Selection opens a public Dialog with right placement and non-modal behavior; focus and dismissal remain library responsibilities. Search accepts PascalCase and snake_case names. Copy falls back to selecting the import text when clipboard access is unavailable. It has no private library imports or duplicated component styles.

Run `npm run dev` from the repository root for local live development. `npm run build` produces the library and one self-contained offline documentation HTML file. All pages use hash routes, including `#/getting-started` and `#/components/buttons/preview`; the release needs no server or sibling assets.

`src/Reference.ts` is the stable entry shared by the application and package build. Maintained reference content lives in `src/reference/`, with one file per component family, foundation content, setup snippets, shared types and `UsageMarkdown.ts` for the package's generated `USAGE.md`. Foundations document the shared rules and their APIs: Typography owns Text, Colors & themes owns Theme, and Icons & assets owns icon/brand usage. Component groups follow purpose, from layout and surfaces through actions, forms, navigation, content and feedback.

`src/App.tsx` owns the documentation shell and appearance. `src/pages/` holds Overview, Getting started and the Catalogue embedded in Overview; `src/navigation/` holds the sidebar, topic icons, previous/next links and the hash route subscription. Overview is a centered hub with a component catalogue grouped by purpose. Every page follows the selected appearance; the theme button switches the entire documentation between light and dark.

`ReferenceContent` renders ordinary topics with public Tabs for Preview, Guidelines and Usage. Info chips and Disclosure notes use compact single-page references; Composition & extension is a guide with code examples. `src/Documentation.ts` owns routes, legacy aliases and the reading order. Previous/next links move between topics and retain the current view. Legacy links resolve to their consolidated topics: Text to Typography, Icon buttons to Buttons, Input/Textarea to Text fields, Responsive layout to Spacing & shape, Motion to Accessibility, and notes to Disclosure notes. The former standalone component catalogue resolves to Overview’s component section. Compact references and guides ignore old view suffixes.

Keep shared rules in foundations and component behavior on its own page. Buttons owns Button and IconButton; Text fields owns Input and Textarea, with separate usage contracts. Accessibility documents library/application responsibilities and keyboard behavior, followed by motion defaults. Composition & extension explains public primitives, root composition and product wrappers; its sections also generate the package usage guide. Related-topic links connect them without repeating demonstrations: spacing shows tokens, layout shows Stack/ActionGroup, and grouped rows show connected geometry.

`src/Documentation.css` owns documentation layout and artificial state specimens only. Theme, typography, colors, controls, cards and feedback are supplied by the package. Each preview renders once and retains its interaction state when the theme changes.

Headers, previews, articles, catalogues and page navigation share one centered content frame with equal side gutters. Text and specimens keep their own alignment inside that frame. PageNavigation uses the public DirectionLinks component to center adjacent previous/next destinations, including a single destination at either end of the reading order. Documentation owns bottom placement and outer spacing; the library owns the link grouping.

`PageHeader` composes a page banner from Card, Stack and Text, with view tabs. Overview uses its existing logo surface as the banner. The shared theme control switches the entire application.

`src/previews/` groups live examples by component family. Each topic owns its interaction state. Only examples with otherwise irreversible changes offer a local restore control; manual toast specimens can be restored after dismissal. Reversible controls need no reset button; `Preview` supplies one specimen area using the current theme. Foundation demonstrations live in `src/previews/foundations/`; measured token values refresh when the theme changes. `Example` is a private specimen frame composed from public Stack and Text. The catalogue uses Card links and the overview uses Button links. Managed toasts inherit the same theme as their controls. Examples use public props rather than selectors into component internals.

Keep routes, previews, token measurements, code blocks and prop tables here. Reusable interaction, visual variants and spacing contracts belong in `packages/ui`; do not recreate them in the documentation.

Surface is the visual base for background fill, padding and corners. Card builds on Surface with standard content layout; specialized cards add their own composition. Stack and ActionGroup own layout. Use Surface for plain panes and compose an existing layout element through `render` when both belong on the same root. The overview hero consumes Surface; content card specimens use Card.

Keep previews focused on the subject. Use Text and invisible layout containers for headings, descriptions and tab panels. Do not add decorative Cards, Surfaces, rows, chips or disclosure notes to another component's demonstration. Other visible controls are appropriate only when they demonstrate a required feature, such as tab buttons, action slots, modal triggers or toast delivery. The banner, catalogue navigation and previous/next links are documentation navigation, not specimens.

Example sections share the content frame. Size limits belong to the demonstrated content: compact controls, fields and card specimens have bounded widths; comparison grids use the available column width and reflow as space narrows. Avoid fixed grid column counts, centered individual specimens and arbitrary offsets. Related variants use plain Specimen labels and consistent gaps.

Example links use the current document URL and simulate their destination locally. Preview prevents default link activation, including modified clicks and auxiliary clicks, without stopping component handlers. Keep this behavior in the documentation; product links retain normal navigation. Sidebar, banner views, catalogue links and previous/next page navigation are outside the preview boundary.
