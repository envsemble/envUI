# Documentation application

The shell uses a fluid sidebar on desktop and a compact header below 48 rem. Its navigation opens in the public Dialog, closes after choosing a destination and returns focus to the main content. Growing the viewport back to desktop dismisses the mobile dialog. Grids reflow within their content container; typography and spacing retain the shared relative scale, including enlarged browser text. Comparison tables and code scroll locally.

This React application consumes only public envUI exports. Ordinary examples use per-icon `@envsemble/envui/icons/Name` imports. The offline Icons & assets catalogue intentionally imports the full public icon barrel and renders 72 results per page. A compact icon grid puts the symbol above its label, with common icons first and an outline/filled switch. Selection opens a public Dialog with right placement and non-modal behavior; focus and dismissal remain library responsibilities. Search accepts PascalCase and snake_case names. View usage opens the same page’s Usage tab with the selected symbol’s exact import and filled state. CodeBlock owns copying and its manual-selection fallback. The catalogue has no private library imports or duplicated component styles.

Run `npm run dev` from the repository root for local live development. `npm run build` produces the library and one self-contained offline documentation HTML file. All pages use hash routes, including `#/overview/get-started` and `#/components/buttons/preview`; the release needs no server or sibling assets.

`src/Reference.ts` is the stable entry shared by the application and package build. Maintained reference content lives in `src/reference/`, with one file per component family, foundation content, setup snippets, shared types and `UsageMarkdown.ts` for the package's generated `USAGE.md`. Foundations document the shared rules and their APIs: Typography owns Text, Colors & themes owns Theme, and Icons & assets owns icon/brand usage. Component groups follow purpose, from layout and surfaces through actions, forms, navigation, content and feedback.

`src/App.tsx` owns the documentation shell and appearance. `src/pages/` holds Overview and its Catalogue and GettingStarted content; `src/navigation/` holds the sidebar, topic icons, previous/next links and the hash route subscription. Overview has a centered logo above Components and Get started tabs. Components shows the card catalogue grouped by purpose; Get started contains installation, first-component, local development and upgrade guidance. Getting started has no separate page or sidebar item. The logo uses the existing charcoal text color. Every page follows the selected appearance; the theme button switches the entire documentation between light and dark.

`src/theme/` owns documentation palette customization. On Colors & themes, each token swatch uses a public Button to open a compact public Dialog containing ColorPicker. The library owns the color area, hue slider, HEX validation and keyboard behavior; documentation owns token measurement and temporary palette changes. Rows are grouped by primitive purpose; composed components follow their underlying Button, Surface and field colors. Hover and pressed shades follow each primitive's base color. Edits apply live throughout the documentation, including portals, and stay separate for light and dark. They exist only in memory and reset on page reload; package theme defaults remain hardcoded in `Tokens.css`.

`src/layout/` owns PageHeader and PageViews. `src/previews/ComponentPreview.tsx` and `FoundationPreview.tsx` select the registered topic specimens; `src/pages/ReferenceContent.tsx` composes their reference page. `PageViews` gives foundation and component pages the same Preview and Usage banner tabs. Overview owns its Components and Get started tabs directly through the public Tabs component. Preview integrates design guidance where an example needs it; there is no separate Guidelines tab or appended guideline dump. Usage stays separate for implementation and API contracts, with the official Code icon on its left. `ReferenceContent` supplies topic content, with no compact-page or guide routing exceptions. Composition has live examples and contextual prose in Preview and implementation in Usage. `src/navigation/DocumentationRoutes.ts` owns routes, legacy aliases and reading order. Previous/next links retain Preview/Usage on reference pages and map these to Components/Get started when returning to Overview. Legacy links resolve to their consolidated topics: Text to Typography, Icon buttons to Buttons, Input/Textarea to Text fields, Responsive layout to Spacing & shape, Motion to Accessibility, and notes to Disclosure notes. Old Guidelines URLs open the merged Preview. The former standalone catalogue and Overview Preview links resolve to Overview’s Components tab. Old Getting started and Overview Usage links open the Get started tab, retaining section anchors.

Keep shared rules in foundations and component behavior on its own page. Add concise captions or prose beside the relevant specimens only when they explain a decision or non-obvious behavior. Do not narrate what the example already shows. The maintained reference guidelines also feed the complete package usage guide; they are not automatically repeated on the visual page. Buttons owns Button and IconButton; Text fields owns Input and Textarea, with separate usage contracts. Accessibility documents library/application responsibilities and keyboard behavior, followed by motion defaults. Composition & extension explains public primitives, root composition and product wrappers; its sections also generate the package usage guide. Related-topic links connect them without repeating demonstrations: spacing shows tokens, layout shows Stack/ActionGroup, and grouped rows show connected geometry.

`src/styles/index.css` imports documentation styles in cascade order: shell, preview frames, reference pages, foundations, accessibility, artificial interaction states and responsive/print rules. Theme, typography, colors, controls, cards and feedback are supplied by the package. Each preview renders once and retains its interaction state when the theme changes.

Headers, previews, articles, catalogues and page navigation share one centered content frame with equal side gutters. Text and specimens keep their own alignment inside that frame. PageNavigation uses the public DirectionLinks component to center adjacent previous/next destinations, including a single destination at either end of the reading order. Documentation owns bottom placement and outer spacing; the library owns the link grouping.

`PageHeader` composes a page banner from Card, Stack and Text, with a larger responsive title, an optional reference summary and a faint decorative topic symbol. Heading, summary and Preview/Usage tabs stay centered; all colors come from the existing theme. `TopicIcons` supplies individual banner symbols separately from sidebar group icons. Overview keeps its centered logo above Components/Get started tabs, composed from Surface, Stack and Text. The shared theme control switches the entire application.

`src/previews/` groups live examples by component family. Each topic owns its interaction state. Reversible controls need no reset button; a native form reset is shown when reset behavior is the subject. Static Toast specimens do not dismiss; managed toasts use the public provider. `Preview` supplies one specimen area using the current theme, composed from Theme and Stack. Foundation demonstrations live in `src/previews/foundations/`; measured token values refresh when the theme changes. `Example` is a private specimen frame composed from public Stack and Text. The catalogue uses Card links and Overview uses Tabs. Managed toasts inherit the same theme as their controls. Examples use public props rather than selectors into component internals.

Keep routes, previews, token measurements and prop tables here. Every code snippet enables the public CodeBlock's `copyable` prop; Markdown and editor previews enable `codeCopyable`. Code display and copying use the public CodeBlock; there is no documentation-only highlighter or copy implementation. Reusable interaction, visual variants and spacing contracts belong in `packages/ui`; do not recreate them in the documentation.

Text field previews use the public Input and Textarea components, including their outlined wells, floating labels and bottom-edge validation. Label placement and field styling belong to the library; there are no documentation-only field designs.

Code, Markdown and MarkdownEditor are imported from the public `@envsemble/envui/content` entry. Basic controls remain on the main entry so consumers using only UI controls exclude parsing and highlighting code.

Rich text uses the separate public `@envsemble/envui/rich-text` entry. Its preview composes RichTextEditor and the matching read-only RichText viewer with Card and Tabs; library components own formatting, suggestions and serialization. Documentation supplies small generic contact, file and topic collections, temporary draft state, sample upload results and local reference activation. The Markdown source tab makes stable reference IDs and normalized serialization inspectable. External draft replacement demonstrates the controlled value contract. Reference contracts are maintained in `src/reference/RichText.ts` and feed the generated package usage guide.

Surface is the visual base for background fill, padding and corners. Card builds on Surface with standard content layout; specialized cards add their own composition. Stack and ActionGroup own layout. Use Surface for plain panes and compose an existing layout element through `render` when both belong on the same root. The overview hero consumes Surface; content card specimens use Card.

Keep previews focused on the subject. Use Text and invisible layout containers for headings, descriptions and tab panels. Do not add decorative Cards, Surfaces, rows, chips or disclosure notes to another component's demonstration. DisclosureNote can organize optional documentation such as artificial interaction matrices; its focus and disclosure styling stay in the library. Markdown previews are an intentional exception: use Card directly around their rendered specimens for standard padding and content spacing. Explanations and captions stay outside those cards. Code previews and Usage code blocks use CodeBlock directly, without a surrounding card; CodeBlock retains its GitHub colors. Other visible controls are appropriate only when they demonstrate a required feature, such as tab buttons, action slots, modal triggers or toast delivery. The banner, catalogue navigation and previous/next links are documentation navigation, not specimens.

Code examples belong in Usage on reference pages and Get started on Overview; the Code page alone displays them in Preview because code display is its subject. Setup commands, asset imports, composition implementations and selected-icon imports follow the same rule. Markdown Preview demonstrates prose and formatting; fenced/inline code syntax is documented in Usage. The native Markdown editor still allows users to write and preview their own content. Token names and measurements in foundation previews are specimen metadata, not implementation examples. Application link examples report a local destination rather than navigating away. The renderer owns no resource resolution, product routes or custom reference tokens.

Markdown editor previews consume MarkdownEditor for formatting, selection, undo and preview. The application picker example owns its sample resource choices and dialog state, returning ordinary labels and URLs through onRequestLink. Editor formatting and source-control styles remain in the library. All examples use generic projects, documents and settings; they must not depend on any consuming product's terminology or behavior.

Example sections share the content frame. Size limits belong to the demonstrated content: compact controls, fields and card specimens have bounded widths; comparison grids use the available column width and reflow as space narrows. Avoid fixed grid column counts, centered individual specimens and arbitrary offsets. Related variants use plain Specimen labels and consistent gaps.

Example links use the current document URL and simulate their destination locally. Preview prevents default link activation, including modified clicks and auxiliary clicks, without stopping component handlers. Keep this behavior in the documentation; product links retain normal navigation. Sidebar, banner views, catalogue links and previous/next page navigation are outside the preview boundary.
