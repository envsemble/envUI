# @envsemble/eslint-plugin-envui

## 1.0.0-prerelease.5

### Major Changes

- The `no-renamed-exports` rule is removed. Delete it from any configuration or disable comment that names it: ESLint reports a rule it doesn't know.

### Minor Changes

- The `ThemeValue` type, `'light' | 'dark'`, is `ColorScheme`, as CSS calls it.
- `CommandPaletteActionOptions`, the second argument of CommandPalette's `onAction`, is `CommandPaletteActionDetails`, as every callback's extra argument is named.
- A new rule, `no-raw-graphics`, on as an error in `configs.recommended`, points pictures to envUI's Graphic and icons. It reports a raw `<img>`, which Graphic replaces for logos and, with `fit="cover"`, photos; a raw `<svg>` with a fixed `width`, `height` or `fill`, such as `width="24"`, outside an icon slot or a Graphic, and tells an icon component to write `width="1em" height="1em" fill="currentColor"`, as envUI's own icons do; imports from other icon packages, such as `lucide-react` or `react-icons/fa`; a `<Graphic>` without `alt`; and a margin on a `<Graphic>`, which `npx envui-graphic <file>` replaces by trimming the file's empty edges. Its `allow` option keeps an icon package you still need. See [no-raw-graphics](https://github.com/envsemble/envUI/blob/main/packages/eslint-plugin/README.md#no-raw-graphics).
- Bar, Rail and Drawer are NavigationBar, NavigationRail and NavigationDrawer, with `NavigationBarProps`, `NavigationRailProps`, `NavigationDrawerProps` and `NavigationDrawerDestination`, after Material's navigation bar, rail and drawer: elsewhere a drawer is a panel over the page, and Bar named nothing in particular. Their part classes and color properties take the same names, `env-navigation-bar-*`, `env-navigation-rail-*` and `env-navigation-drawer-*` where they were `env-bar-*`, `env-rail-*` and `env-drawer-*`, and their style sheets are `NavigationBar.css`, `NavigationRail.css` and `NavigationDrawer.css`. The documentation page is `navigation-drawer`; `drawer` opens it.
- `envui/no-hand-rolled-layout` is `envui/no-inline-layout`, after what it reports: flex and grid layout in inline styles, as `no-raw-colors` reports colors there. Rename it in your config and disable comments.

### Patch Changes

- `envui/no-inline-layout` reads a style through optional chaining and a non-null assertion, as `envui/no-html-elements` reads a component: `style={styles?.toolbar}` and `display: d!` are now reported where the constant they read sets a layout display.
- Success, information and danger toasts take the neutral toast's dark fill, `--env-color-bg-neutral-strong`, with their icon in the tone's light grade on a faint disc of it, rather than a solid green, blue or red fill, so a notification no longer outweighs everything on a busy screen. The icon colors are new tokens, `--env-color-fg-success-on-strong`, `--env-color-fg-info-on-strong` and `--env-color-fg-danger-on-strong`, at 3:1 on the disc, 4.5:1 at high contrast; a toast whose content color is set takes that color for its icon too. `--env-color-bg-{success,info,danger}-strong` stay. Every toast in a region is one width, 22 rem, less the gutters on a phone, so a stack's edges line up rather than following each message's length. The ESLint plugin and the Stylelint config accept the new tokens.
- The token lists the messages suggest include `--env-color-rating-star`, the filled stars' gold of a Rating.

## 1.0.0-prerelease.3

### Major Changes

- Part names are public; component tokens are private.
  - **Part classes and state attributes are public and versioned.** Every part of a component has a class, `env-<component>-<part>`, such as `.env-card-header`, and a component shows its state in `data-*` attributes, such as `[data-tone='danger']`. An application's CSS may target them, and from now on a release that renames or removes one is a major release with a migration note. `docs/generated/parts.json` lists every component's root class, its parts with what each one is, and its state attributes with their values; the manifest gives each component page its `parts`, the MCP server's `get_component` returns them, and llms.txt names each component's root classes.
  - **Component tokens are private.** The custom properties a component declares for itself, such as `--env-card-padding` or `--env-badge-fill`, may change in any release. Set the system tokens, such as `--env-space-4` or `--env-color-bg-muted`, instead.
  - **The `no-private-classes` rules are removed** from the ESLint plugin (`envui/no-private-classes`) and the Stylelint config (`envui/no-private-classes`), since the classes they reported are public now. To migrate, delete the rule from any configuration or disable comment that names it: ESLint and Stylelint report a rule they don't know.

  Migration guide: [Part names and component tokens](https://github.com/envsemble/envUI/blob/main/docs/migration.md).

### Minor Changes

- A new rule, `no-hand-rolled-layout`, warns on `display: flex`, `inline-flex`, `grid` and `inline-grid` in JSX `style` objects and names the layout primitive to use instead: Row for a flex row, Column for a flex column, and Grid for a grid. It reads every object in a `style` value, through conditions, spreads and calls, a `const` of the same file that holds the style object, as in `style={row}` or `style={styles.toolbar}`, but not one passed to a call, as in `style={css(config)}`, and a `const` that holds the display, as in `display: d`. `configs.recommended` turns it on as a warning, not an error, since plain CSS stays allowed where a primitive can't do what the layout needs; disable it on that line and say why.

### Patch Changes

- The soft accent badge takes a tint of its own, `--env-color-bg-accent-badge`: in the light theme the accent blue at 5%, fainter than `--env-color-bg-accent-muted` at 12%, so its blue text keeps 4.5:1 on list rows and muted surfaces. The blue itself is unchanged. In dark and at high contrast the new token has the value of `--env-color-bg-accent-muted`, and info alerts keep `--env-color-bg-accent-muted` in every theme. The ESLint plugin and the Stylelint config accept the new token.
- Any surface can become its own skeleton, and the Skeleton component goes.
  - `skeleton` on Surface, Card, List.Root and List.Item, Table.Root, Alert, Message, TopBar, Drawer, Rail, Bar, Dialog, Sheet, Popover, HoverCard, Menu.Root and Panes.Supporting shows the component, and everything inside it, as a skeleton: text becomes bars as long as the text, icons, avatars, media and controls become filled shapes of their size, a navigation's destinations bars and icon shapes, and backgrounds, borders and corners stay. Its root is marked `data-env-skeleton` and is the one busy region, `aria-busy`, that assistive technology hears; its content, in `env-skeleton-content`, a wrapper without a box of its own, is inert. A list, whose rows must be its children, is inert as a whole, with a visually hidden status, `env-skeleton-status`, beside it that says what is loading. Turning `skeleton` on or off renders the content anew. Every bar and shape pulses in step across the page, and keeps still with a reduced-motion preference.
  - `placeholders<Item>(count)` returns stand-in items, `Placeholder<Item>`: an `id`, `envui-placeholder-0` and so on, and every other field of `Item` possibly undefined, so a page writes `items ?? placeholders<Item>(3)` and renders its normal components while the items load. Text given as undefined, such as `title={item.title}`, is a bar of its text style's usual length; `isPlaceholder(item)` tells a stand-in apart by its id, also once serialized, and `useSkeleton()` tells a component of the application's own that it is inside a skeleton.
  - Skeleton and `SkeletonProps` are removed, with the `env-skeleton` class and its `data-emphasis`, and so is NavList.Skeleton, with `env-nav-list-skeleton`, `env-nav-list-skeleton-item` and its `data-icon-only`: render the components themselves with `skeleton`. Loading with no known shape is a Spinner with its label shown, `showLabel`. CodeDiff shows one while its highlighter loads.
  - Dev mode's `envui.layout.skeletonShift(root)` toggles a skeleton and reports, as `skeleton-shift` problems, the elements that move or resize when it loads, and media without an aspect ratio or a size of its own.
  - `v1-names` reports `Skeleton` and `SkeletonProps`, and `v1-classes` `env-skeleton`, `env-skeleton-highlight` and NavList.Skeleton's classes, with what to use instead; Skeleton's `tone` no longer moves to `emphasis`. `envui/no-renamed-exports` reports Skeleton too.

  Migration guide: [Skeletons](https://github.com/envsemble/envUI/blob/main/docs/migration.md).

A name keeps the hue it had, now under its new name.

  The tokens follow: `--env-color-avatar-bg-teal` and the others are `--env-color-avatar-bg-seafoam` and so on, with `--env-color-avatar-fg-{hue}` and `--env-color-avatar-figure-{hue}` beside them, and each hue, powder included, has tokens of its own. `--env-color-avatar-bg`, `--env-color-avatar-fg` and `--env-color-avatar-figure` stay, the powder hue's.

A fill you set on an old `--env-color-avatar-bg-{hue}` for a color of your own now sits under the hue's deep foreground, so set `--env-color-avatar-fg-{hue}` and `--env-color-avatar-figure-{hue}` beside it, to a color that keeps 4.5:1 on that fill. The ESLint plugin and the Stylelint config know the new token names.

- CounterBadge folds into Badge: a Badge with `count` is a compact count.
  - `<Badge count={12} />` shows a count, a number or short text such as 99+, in a compact round pill with tabular figures, in place of a label. It takes the tones and variants of any badge: neutral and soft by default, with the figures in the default text color, and `tone="accent" variant="solid"` for the filled count that needs attention. Its `aria-label`, such as 12 unread, is read in place of the number.

- Drawer, the panel that slides in over the page, is Sheet, after Material's side and bottom sheets; the name Drawer is the navigation drawer's. - Row, Column, Grid and Box, the layout primitives, replace Stack: thin wrappers over flex and grid that size to their content and never paint.
  - `<Stack direction="row">` is `<Row>`, with `wrap`, and any other Stack a `<Column>`; `gap`, `padding`, `align` and `justify` take Stack's values, the gap and the padding as steps of the spacing scale. Row and Column have no gap of their own, where Stack's was 1 rem.
  - Grid lays content out in columns: `columns={3}` for three equal columns, a template such as `columns="minmax(0, 2fr) minmax(0, 1fr)"`, or `columns={{ min: '14rem' }}` for as many as fit. Box is a plain block for `padding`, a named size container (`container`) or a named region.
  - Each renders `data-env-layout` (`box`, `row`, `column` or `grid`), `name` as `data-env-name`, and its options as attributes such as `data-gap`, and takes `render`, `className` and `ref`. Its rules have no specificity, so any class overrides them; the `env-stack` class and `StackProps` are gone.
  - The `v1-stack` codemod rewrites each Stack, after `v1-structure` and `v1-render`, and reports a `direction` that is an expression. `envui/no-renamed-exports` no longer reports `Row` and `RowProps`, 0.x's list row, as 1.0 exports `Row` again.

  Migration guide: [Layout primitives](https://github.com/envsemble/envUI/blob/main/docs/migration.md).

- envUI draws no drop shadows. Menus, Select and Combobox lists, popovers, hover cards, pickers, rich text suggestions, docked panels, tooltips, toasts, dialogs, sheets and the command palette separate by their fill, their edge and, for modals, the scrim.
  - The elevation edge, `--env-elevation-{1|2|3}-border`, is clearly visible now, one color for every level: about 2:1 against a popup and the page, and at least 1.6:1 against every surface a popup floats over. In high contrast it stays the 4.5:1 boundary. In dark, the edge of tooltips and toasts, `--env-color-border-{neutral|success|info|danger}-strong`, is this edge too.
  - The elevation shadows `--env-elevation-{0|1|2|3}-shadow` are removed, and with them the 0.7 names `--elevation-{0|1|2|3}-shadow`, which no longer take the prefix. `v1-classes` reports each use. Delete the `box-shadow`. If your own floating layer relied on it, give the layer its level's edge instead: `border: 1px solid var(--env-elevation-2-border)`.
  - A row that moves in a reorderable list takes the elevation edge as a ring, and the color picker's thumbs take a ring outside their white edge. Neither has a shadow any more. Docked panels and the active one are no longer set apart by shadows: the active docked panel's edge takes the accent, `--env-color-border-accent-emphasis`, in every theme and contrast.
  - Focus rings, halos, inset edges and selection bars drawn with `box-shadow` are rings, not shadows, and stay.

SplitPane is rewritten by hand, as supporting Panes with Panes.Main, an optional Panes.Divider and Panes.Supporting.
  - Sizes are in rem: `size`, `defaultSize`, `minSize` and `maxSize` are the resized pane's width, and `persist` keeps it.
  - The part classes go: `env-split-pane`, `env-split-pane-pane`, `env-split-pane-handle`, `env-split-pane-probe`, `env-list-detail`, `env-list-detail-list`, `env-list-detail-detail` and `env-list-detail-back`, which are `env-panes`, `env-panes-main`, `env-panes-supporting`, `env-panes-list`, `env-panes-detail`, `env-panes-divider` and `env-panes-back`. Their state attributes go: `data-orientation`, `data-axis` (the divider keeps it, as every resize handle does), `data-stack-below`, `data-stacked` and `data-detail-shown`; Panes has `data-behavior`, `data-split-at` and `data-open`.
  - A vertical split pane has no counterpart.
  - `v1-classes` renames the classes of SplitPane and ListDetail to Panes', `env-split-pane-handle` to `env-panes-divider` and `env-list-detail-back` to `env-panes-back`, and reports `env-split-pane-probe` and the states Panes no longer sets, such as `[data-stacked]`.

  Migration guide: [Split panes](https://github.com/envsemble/envUI/blob/main/docs/migration.md).

- LoadingState folds into Spinner: a Spinner with `showLabel` shows its label beside it.
  - `<Spinner label="Loading project" showLabel />` is a status line for loading with no known shape: a busy `role="status"` that centres the spinner and its muted label in its row, the label read as the status. Without a `label` it says Loading, from EnvUIProvider's `messages.common.loading`. The label is `env-spinner-label`, and the spinner carries `data-show-label`. Without `showLabel`, a Spinner is as it was: a progress bar named by `label`, or hidden.
  - LoadingState and `LoadingStateProps` are gone: `<LoadingState label>` is `<Spinner label showLabel>`, and `env-loading-state` and `env-loading-state-label` are `.env-spinner[data-show-label]` and `env-spinner-label`. CodeDiff shows its loading so.
  - `v1-structure` rewrites a LoadingState without children into the Spinner and reports the children of one that has them; `v1-names` renames `LoadingStateProps` to `SpinnerProps`, and `v1-classes` renames the classes. A structure case can be `childless`, for elements without children. `envui/no-renamed-exports` reports LoadingState with what replaces it.

  Migration guide: [Folded components and patterns](https://github.com/envsemble/envUI/blob/main/docs/migration.md).

- WindowFrame and AccountMenu are patterns now, not components: they are arrangements of other components that applications arrange differently.
  - WindowFrame, with WindowFrame.Root, WindowFrame.TitleBar and WindowFrame.Content, is a Scaffold with `topBarSpan="full"` and a `<TopBar titleBar>`, whose body scrolls below the title bar; its `bodyRef` is the content's ref. The window frame pattern shows it. The part classes `env-window-frame`, `env-window-frame-content`, `env-window-frame-title-bar`, `env-window-frame-title-bar-layout`, `env-window-frame-title-bar-start`, `env-window-frame-title-bar-center` and `env-window-frame-title-bar-end` go: a title bar is `.env-top-bar[data-title-bar]`, with `env-top-bar-start`, `env-top-bar-title` and `env-top-bar-actions`.
  - AccountMenu, with AccountMenu.ThemeSubmenu and AccountMenu.OrganizationSubmenu, is a Menu.Root whose trigger is an AvatarButton, with a Menu.Header of the Avatar and the name, and a Menu.Submenu around a ThemeRadioGroup for the theme. The account menu pattern shows it. The part classes `env-account-menu`, `env-account-menu-header`, `env-account-menu-header-text`, `env-account-menu-header-name`, `env-account-menu-header-description`, `env-account-menu-trigger`, `env-account-menu-trigger-text`, `env-account-menu-trigger-name` and `env-account-menu-trigger-description` go, and with the trigger its `data-popup-open`, which every Menu.Root trigger still has.
  - The `v1-structure` codemod no longer rewrites 0.x's WindowFrame, or SplitView, into 1.0.0-prerelease.0's parts: `v1-names` reports WindowFrame, TitleBar, SplitView and AccountMenu where they are used. `v1-classes` renames WindowFrame's parts to the TopBar's and the Scaffold's, as listed above, and reports `env-window-frame` itself, `env-window-frame-title-bar-layout` and the `env-account-menu-*` classes.

  Migration guide: [Shell, dock, editors and code](https://github.com/envsemble/envUI/blob/main/docs/migration.md).

## 1.0.0-prerelease.0

### Major Changes

- envUI's CSS moves into cascade layers, and every token takes the `--env-` prefix.
  - **Cascade layers.** Every rule of `styles.css` is in a layer of `env`: `env.reset`, `env.tokens`, `env.base`, `env.components` and `env.utilities`, in that order. An application's CSS outside cascade layers overrides envUI's whatever its specificity, so selectors and `!important` that only out-weighed envUI's rules can go. An application puts its resets and element styles in a layer before `env` and its own layers after it, declared once, such as `@layer reset, env, app;`: an element rule outside layers would restyle envUI's components too. The font face stays outside layers.
  - **The `--env-` prefix.** Every token is a custom property with the prefix: `--space-4` is `--env-space-4` and `--color-fg-muted` is `--env-color-fg-muted`, in Tokens.css, the token reference, the manifest and the MCP server. The application hooks take it too: `--env-line-height-body`, `--env-avatar-group-ring` and the pill corner `--env-radius-full`.
  - **The 0.7 aliases are removed.** `--color-text-muted`, `--color-row`, `--color-checkbox` and the other 0.7 names that were aliases of the semantic roles are gone; use the role that replaces each. The list item's per-theme fill and the avatar's fixed blues are component tokens now: `--env-color-list-item-bg` with `-hover` and `-pressed`, and `--env-color-avatar-bg`, `-fg` and `-figure`. `--md-sys-shape-corner-*` is retired for one radius scale, `--env-radius-{none|xs|sm|md|lg|xl|full}`, with `--env-radius-surface` and the row radii as its roles; `--radius-standard` is `--env-radius-sm` and `--radius-large` `--env-radius-lg`.
  - **Consistent color names.** A tone's edges grow from `border-{tone}-muted`, an alert's faint edge, through `border-{tone}`, an outlined badge's translucent edge, to the solid `border-accent-emphasis` and `border-danger-emphasis`, the edges of a focused and an invalid field, which were `border-accent` and `border-danger`. `border-translucent` is `border-media` and `bg-page-muted` is `bg-inset`, named for their roles, and the tones' state layers gain a resting `bg-{tone}-subtle`.
  - **Forced colors.** Under `forced-colors: active`, such as the system's contrast themes, selected, chosen, current, highlighted, checked, focused, invalid and unavailable states take system colors where a fill or shadow carried them, so they stay visible, and swatches, the color picker and calendar heatmaps keep their colors.
  - **Motion** lives in each component's style sheet; it is unchanged, with fades always and movement only without a reduced-motion preference.

  To migrate, run `npx @envsemble/envui-codemods v1-classes src`: it rewrites the old custom properties in style sheets and scripts, declared or read, to their 1.0 names, the 0.7 aliases straight to the tokens that replace them, and reports `--color-white`, `--color-canvas-dark` and the removed names with what to use instead. The migration guide lists every name. The ESLint plugin and the Stylelint config suggest the prefixed tokens.

  Migration guide: [Cascade layers](https://github.com/envsemble/envUI/blob/main/docs/migration.md) and [Tokens](https://github.com/envsemble/envUI/blob/main/docs/migration.md).

- The first release: ESLint rules for applications built with envUI, for ESLint 10 flat config. They report what envUI already provides but the code builds by hand, and each message names the envUI component or token to use and how to import it. `configs.recommended` turns every rule on as an error.
  - `no-html-elements`: raw `<button>`, `<input>` by type, `<select>`, `<textarea>`, `<dialog>`, `<table>`, `<details>`, `<progress>`, `<meter>` and `<kbd>`, anchors used as buttons, raw links, focusable elements that handle clicks, and widget roles such as `role="menu"`, each with the envUI component that replaces it. What a part renders through `render`, hidden inputs and entries named in `allow` pass.
  - `no-private-classes`: envUI's `env-` classes in `className`, class-name helpers, `classList`, DOM and browser-test selectors and style sheets written in JavaScript. `env-theme` is allowed.
  - `no-raw-colors`: literal colors in inline styles, also hex colors built in a template literal such as `` `#${hex}` `` or by concatenation such as `'#' + hex`, also through calls, such as `darken('#123456', 0.1)` or a style object passed to a helper, but not strings that only choose a style, such as a member's key or the selector given to `querySelector`, `closest` or another DOM lookup, with the envUI color tokens to use instead. Like the Stylelint config, it follows `var()` fallbacks eight levels deep, in the channels and the alpha alike, and reports deeper nesting; an alpha is a literal number or percentage or a `var()`.
  - `no-renamed-exports`: names that envUI 0.7 exported and 1.0 renamed or made internal, with the 1.0 name, and names that became namespaces, such as `Menu`, rendered as components.

  An application that re-exports envUI from a module of its own lists it in `settings.envui.reexportModules`: `no-html-elements` and `no-renamed-exports` then count the names imported from it as envUI's. A path, best written absolute as `path.resolve(import.meta.dirname, 'src/ui')`, names the module's file, and matches every relative import that resolves to it, with or without its extension or `/index`; a relative entry such as `./src/ui` is read from ESLint's working directory, and an entry that names no existing module is a configuration error. An alias such as `@/components/ui` matches as written. `no-renamed-exports` then says to update that module first and rename imports through it by hand, since the v1-names codemod rewrites imports from `@envsemble/envui` only.

  The plugin is released with `@envsemble/envui` at the same version; install the version that matches envUI.

  Migration guide: [Upgrade from envUI 0.x to 1.0](https://github.com/envsemble/envUI/blob/main/docs/migration.md).

### Minor Changes

- `envui/no-html-elements` points a raw `<input type="time">` to `TimePicker` and a raw `<input type="month">` to `MonthPicker`, in place of `TextField`, and the note on an `<input>` of another or a computed type names both.
- Menus, navigation and collections take the 1.0 vocabulary, and several of their bugs are fixed.
  - Menu: `Menu.Item`'s `trailing` is `end`. An item with `href` closes the menu as it is followed and runs its `onClick`, if any, such as for analytics, and a disabled one renders no link, so nothing follows it. Every menu's popup, Menu.Root's, Menu.Submenu's, ContextMenu's and Menubar.Menu's, is the shared popup surface in the theme, scale and text direction of its trigger; Menu.RadioGroup takes `aria-labelledby`, which OrganizationSwitcher points at its heading; Menu.Root takes `side="inline-start"` and `"inline-end"`, and these parts pass `ref`, `style` and data attributes to the popup.
  - OrganizationSwitcher: `organizations`, `currentOrganizationId` and `onSelect` are `items`, `value` and `onValueChange`; `OrganizationSwitcherOrganization` is `OrganizationSwitcherItem`, whose `detail` is `description`. Its rows are Menu.RadioItems, and its strings come from `messages.organizationSwitcher`.
  - NavList.Item: `trailing` is `end`. An icon-only item, or one named by `aria-label`, says its end content in its name: a number, or a CounterBadge without `aria-label`, as a count, such as "Inbox, 12 new", from `messages.navList.itemCount`, and a CounterBadge's `aria-label` or other content's text as it is, such as "Inbox, 12 unread" or "Labs, Beta", from `messages.navList.itemEnd`; the dot alone was hidden from assistive technology. `env-nav-list-item-selected` and `-icon-only` are `[data-selected]` and `[data-icon-only]`.
  - Tabs pass the text direction to their list, so the arrow keys follow it in right-to-left text, while the panels keep the direction around them. `env-tab` and `env-tab-panel` are `env-tabs-tab` and `env-tabs-panel`.
  - DocumentTabs is rebuilt on Base UI Tabs: each tab sits beside its close button instead of around it, a CloseButton out of the tab order and hidden from assistive technology, and announces Delete and Backspace, which close it, through `aria-keyshortcuts`; each tab opens a context menu with Close, also without `onCloseAll`, which adds Close all tabs and the strip's own menu. A ContextMenu `content` function that returns `null` leaves the menu closed on that element. The arrow keys and the wheel follow the text direction; strings come from `messages.documentTabs`; the strip takes `ref` and `style`. `env-document-tab`, `-label` and `-close` are `env-document-tabs-tab`, `-tab-label` and `env-document-tabs-close`, and a new `env-document-tabs-item` holds each tab and its close button.
  - Breadcrumbs: a label cut short shows in full in a tooltip on hover and keyboard focus, and a plain level or the current page cut short takes keyboard focus for it; the name comes from `messages.breadcrumbs`; the `nav` takes native props. `env-breadcrumb` and `env-breadcrumb-*` are `env-breadcrumbs-item` and `env-breadcrumbs-*`.
  - Pagination formats its range in the locale and takes its strings from `messages.pagination`. Pager takes its labels from `messages.pager`, and its children render between the `previous` and `next` props' links.
  - Tree: `selectedId` and `onOpen` are `value` and `onAction`, `TreeOpenOptions` is `TreeActionOptions`, and a TreeItem's `detail` and `trailing` are `description` and `end`; it takes `ref` and `style`. `env-tree-row`, `-detail` and `-trailing` are `env-tree-item`, `-description` and `-end`, and the row height's custom property, `--env-tree-row-height`, is `--env-tree-item-height`; the `--env-tree-row-padding-block-*` tokens keep their names.
  - Table: `Table.HeaderCell`'s `onSort` is `onSortChange`, called with the order pressing asks for. A table named by `aria-labelledby` names its scroll region too. The sort and resize words come from `messages.table`.
  - List: `List.Item`'s `title` and `detail` are `label` and `description`. `List.Root`'s `contrast` is gone: a list in `<Surface background="muted" padding={3}>` of its own takes the raised row fill.
  - Kbd reads `--env-kbd-size`, `-padding-inline`, `-radius`, `-fg`, `-font-size`, `--env-kbd-separator-padding-inline` and `-font`, which a container sets to show smaller keys.

  Migrate with the codemods: `envui-codemods v1-props` renames `trailing`, OrganizationSwitcher's, Tree's, Table.HeaderCell's and List.Item's props; `v1-structure` wraps a `contrast` List.Root in a muted Surface and reports a computed one; `v1-names` renames `OrganizationSwitcherOrganization` and `TreeOpenOptions`; and `v1-classes` renames the classes, `env-menu-theme` to `env-popup-theme` among them, and turns NavList's modifiers into attributes; it reports OrganizationSwitcher's `env-organization-menu-radio` and `-radio-dot`, whose radio is Menu's `.env-menu-item-check` and `-check-mark` now, and a selector that puts `.env-document-tabs-close` inside `.env-document-tabs-tab`, its sibling now. By hand: the `detail` and `trailing` fields of Tree and OrganizationSwitcher data, which TypeScript reports, and the count in an icon-only NavList.Item's `aria-label`, which the item now adds itself. The ESLint plugin reports the renamed types.

  Migration guide: [Navigation and collections](https://github.com/envsemble/envUI/blob/main/docs/migration.md).
