# Changelog

## 1.0.0-prerelease.4 — 2026-10-25

The fourth prerelease of envUI 1.0. Its documentation is one file per page, which the catalogue shows to people, the Docs to developers and the package to coding agents, with each example's code once; one prompt and a hosted skill set envUI up with a coding agent in place of the package's own agent tooling; dev mode opens in a tab of its own, rebuilt on today's envUI; and Drawer gains nested sections and TableOfContents is new. It removes the `envui` command, its MCP server, the packaged skills and the agent plugin: the [migration guide](https://github.com/envsemble/envUI/blob/main/docs/migration.md) says what replaces them.

### Major Changes

- One prompt sets envUI up with a coding agent, and the package's own agent tooling is gone. Agents read the documentation the package ships, which a few lines in the project's `AGENTS.md` lead them to.
  - The prompt `Set up envUI in my app: envui.envsemble.com/SKILL.md`, on the Docs' home with a copy button, leads an agent to the setup skill the site hosts. After a short checklist that waits for a yes, it installs envUI at an exact version from GitHub Packages with its styles and theme, adds the `AGENTS.md` pointer, and turns on the ESLint plugin and the Stylelint config at the same version; the pointer and the lint rules are recommended, and any step can be skipped. In an application with UI of its own, it changes none of it and offers to plan a migration. The site also serves `llms.txt`, an index of the Docs.
  - Removed: the `envui` command (`bin`) with `envui agents` and the `envui mcp` server; the envui-use, envui-migrate and envui-contribute skills under `skills/`; the `envui` agent plugin and its marketplaces; and `manifest.json`, `llms.txt` and `llms-full.txt` at the package root. The Docs' Agent skills page opens For agents.
  - Migration: remove an `envui` MCP server from the project's or client's configuration, copied skill folders, the plugin and its marketplace, and `npx --no envui agents --check` from CI; replace the index between `<!-- BEGIN envui -->` and `<!-- END envui -->` with the pointer; and read `docs/index.md`, `docs/generated/props.json` and `docs/generated/parts.json` where code read the manifest. Running the setup prompt does most of this. The [migration guide](https://github.com/envsemble/envUI/blob/main/docs/migration.md#templates-and-agent-tools) lists each step.

### Minor Changes

- Dev mode opens in a tab of its own, is rebuilt on today's envUI, and keeps up with the page.
  - The Dev mode button and Alt+Shift+D open the page in a new tab with dev mode over the whole window, marked by the `envui-dev` query parameter, which `installDevMode()` reads there; the page they came from stays as it was. Dev mode's tab has no close button and Esc doesn't leave it: closing the tab ends it. The handle's new `openInNewTab()` does the same from code; `open()`, `close()`, `toggle()` and the `open` option open and close dev mode over the page itself, as before, where Esc still closes it. `open()` called right after `installDevMode()` now always opens it.
  - The 3D view's toolbar is four dropdowns whose names show at once on hover: View, the angles laid out as they look at the page, Top above Front, Left and Right beside it and Tilted in the top right corner, each turning the view there with the whole page in view; Show, the planes' names, padding and gaps, only the selected and color by window class; Responsive, the responsive frame, then its device and orientation, which apply while it is on; and View settings, with a Performance panel of the frame rate and what measuring costs. How to move around is a button in the view's top right corner and dev mode's theme is at the foot of the node tree. Each control has one place: the Close button, Fit, the frame's × and its handles' double click are gone, and the Nodes and Inspector buttons leave the toolbar: each sidebar hides with the button in its header, which stays in that top corner of the window while the sidebar is hidden.
  - The sidebars resize by their inner edge, with the grip, keys and double click of a resizable Drawer, up to all the window leaves beside the other sidebar and a narrow view, and dev mode remembers their widths and which are hidden. The inspector's Details and Readout are Tabs, the readout's copy button is a CopyButton, and the readout's lines wrap to the sidebar, indented under their own start.
  - The responsive frame lays the page out wider or taller than the window and whatever holds the root, with whole planes: nothing outside the root, nor the window, cuts them off. While the page resizes, a plane whose picture is of another size shows its outline, name and spacing until the page settles; the pictures are then copied a few each frame. A transition or an animation that ends in the page, and a node that resizes, are measured again.
  - Dragging the 3D view always turns it: pressed on text selected across it, such as after Ctrl+A, the browser no longer drags the selection as a picture, which stopped the view turning. The wheel over the view scrolls the page and zooms smoothly rather than notch by notch, and hovering the node tree no longer renders the view.
  - Dev mode's style sheet is in envUI's components layer, its rules on its own parts of no specificity, from envUI's tokens; the view glides to an angle unless reduced motion is preferred, and the legend makes way in a narrow view.

- Drawer nests destinations in sections that open and close, such as a documentation site's pages: a destination's `children` show under it, indented, with a chevron that flips as Select's does, and the sections that hold the current destination open as it becomes current. A section with `href` or `onSelect` is a link or button with a button at its end, named with the new `messages.navigation.contents`, such as Projects contents; one with neither is only its heading, a button. Each section's button reports `aria-expanded`, and a closed section keeps its links in the page, hidden until found, so search engines follow them and find in page opens it; the expand animation stops under reduced motion. `expanded`, `defaultExpanded` and `onExpandedChange` keep the open sections, named by `href` or label. Rail and Bar show the top level, where a destination whose `children` hold the current one takes the current fill and reports `aria-current="true"`. The new parts are `env-drawer-branch`, `env-drawer-branch-row`, `env-drawer-toggle`, `env-drawer-chevron` and `env-drawer-children`.
- TableOfContents, the page's sections as links, nested by level, with the section the reader is in marked as they scroll: a short dash before each section, like a ruler, which swells in a smooth wave around the reader's place as the page scrolls: the current section's the longest and darkest, the next ones growing as the reader nears them, and the one under the pointer longer too; the sections still to come are quieter and nested sections step in, their dashes the same. It reads the headings in a container, `[2, 3]` by default through `levels`, giving those without an id one, or takes sections of your own as `items`, any element with an id under a label of yours. A link scrolls smoothly to its section, at once where reduced motion is preferred, below a sticky header's scroll margin, adds it to the address and moves focus to it. The landmark is named On this page, from `messages.tableOfContents`, and the current link takes `aria-current="location"`.
- `tooltipDelay` on Toolbar.Root sets how long, in milliseconds, the pointer rests on a Toolbar.Button or Toolbar.Link before its tooltip opens, 400 by default as Tooltip's `delay`; 0 shows every name at once, for a toolbar people scan by pointing, such as a canvas's view controls.
- CommandPalette shows an empty state in place of the list when there are no options: a quiet icon on a muted circle, a title and a quieter description, centred, which the polite status announces with the icon hidden from assistive technology. Before people type it invites a search, with the Search icon and Type to search (`messages.commandPalette.emptyQuery`); when the text finds nothing it shows SearchOff, No results (`messages.commandPalette.empty`) and `messages.commandPalette.emptyHint`, which quotes the text and suggests checking the spelling. `emptyLabel` still sets the title, and the new `emptyDescription` and `emptyIcon` set the description and the icon, `null` hiding either. The new `defaultItems` show while the search field is empty, in place of `items`, such as recent documents or suggestions under a group heading, and are highlighted and chosen like any result; the empty state shows only when there are none.

### Patch Changes

- Every component, pattern and foundation page of the documentation ships as one file per page, in one order: the frontmatter lists each example file once, with its role and caption, then Variants (Options on a foundation), Anatomy, Behaviour, Rules, Accessibility, Words to use and Compose, with each example's code once. The foundations gain the words, figures' legends and rules they had only in the catalogue.
- Slider's fill is empty at the minimum and fills the whole field at the maximum, in proportion between, and ends where the pointer chooses the value; near either end the handle keeps clear of the rounded edge. Dragging or double-clicking a slider no longer selects its label or value.
- Slider stretches a little when dragged past either end, as a rubber band: the value stays at the minimum or maximum while the field stretches toward the pointer from its other end and thins slightly, giving less the further the pointer goes, up to 6% of its length or half its height, and springs back once let go. The label and the value keep their shape and size. Only a drag stretches it, not a press or the keyboard, nor a disabled slider, and it doesn't stretch where reduced motion is preferred.
- Markdown keeps its elements when it renders again with a new `renderLink`, such as an inline function: the headings, links, code and tables it renders are the same elements, so a page's anchors, focus and scroll position survive, and only what changed renders again. TableOfContents follows the page's scrolling also after its sections render anew, where its marks once stayed on the section a link had chosen.
- DatePicker, TimePicker and MonthPicker open one picker card, with the same inset, corners, gaps and footer: TimePicker's popup takes DatePicker's spacing, so Now and Clear no longer sit at its edges, and the actions of all three line up with the body, the shortcut at the start and Clear at the end. The card's parts are `env-picker-popup`, `env-picker-popup-body`, `env-picker-popup-footer` and `env-picker-popup-footer-end`; the popups keep `env-date-picker-popup`, `env-time-picker-popup`, `env-month-picker-popup`, `env-date-picker-actions` and `env-date-picker-actions-end` beside them.

## 1.0.0-prerelease.3 — 2026-10-25

The third prerelease of envUI 1.0, and the first versioned since 1.0.0-prerelease.0: this section gathers the changes of prereleases 1 to 3. It brings Scaffold with the navigation's three forms, Bar, Rail and Drawer, Panes and TopBar; the layout primitives Row, Column, Grid and Box; skeletons from any surface; colors of its own for any element; ColorPicker on its own entry point; dev mode; and no drop shadows. It breaks code written for 1.0.0-prerelease.0: `@envsemble/envui-codemods` makes most of the changes, and the [migration guide](https://github.com/envsemble/envUI/blob/main/docs/migration.md) covers the rest.

### Major Changes

- Any surface can become its own skeleton, and the Skeleton component goes.
  - `skeleton` on Surface, Card, List.Root and List.Item, Table.Root, Alert, Message, TopBar, Drawer, Rail, Bar, Dialog, Sheet, Popover, HoverCard, Menu.Root and Panes.Supporting shows the component, and everything inside it, as a skeleton: text becomes bars as long as the text, icons, avatars, media and controls become filled shapes of their size, a navigation's destinations bars and icon shapes, and backgrounds, borders and corners stay. Its root is marked `data-env-skeleton` and is the one busy region, `aria-busy`, that assistive technology hears; its content, in `env-skeleton-content`, a wrapper without a box of its own, is inert. A list, whose rows must be its children, is inert as a whole, with a visually hidden status, `env-skeleton-status`, beside it that says what is loading. Turning `skeleton` on or off renders the content anew. Every bar and shape pulses in step across the page, and keeps still with a reduced-motion preference.
  - `placeholders<Item>(count)` returns stand-in items, `Placeholder<Item>`: an `id`, `envui-placeholder-0` and so on, and every other field of `Item` possibly undefined, so a page writes `items ?? placeholders<Item>(3)` and renders its normal components while the items load. Text given as undefined, such as `title={item.title}`, is a bar of its text style's usual length; `isPlaceholder(item)` tells a stand-in apart by its id, also once serialized, and `useSkeleton()` tells a component of the application's own that it is inside a skeleton.
  - Skeleton and `SkeletonProps` are removed, with the `env-skeleton` class and its `data-emphasis`, and so is NavList.Skeleton, with `env-nav-list-skeleton`, `env-nav-list-skeleton-item` and its `data-icon-only`: render the components themselves with `skeleton`. Loading with no known shape is a Spinner with its label shown, `showLabel`. CodeDiff shows one while its highlighter loads.
  - Dev mode's `envui.layout.skeletonShift(root)` toggles a skeleton and reports, as `skeleton-shift` problems, the elements that move or resize when it loads, and media without an aspect ratio or a size of its own.
  - `v1-names` reports `Skeleton` and `SkeletonProps`, and `v1-classes` `env-skeleton`, `env-skeleton-highlight` and NavList.Skeleton's classes, with what to use instead; Skeleton's `tone` no longer moves to `emphasis`. `envui/no-renamed-exports` reports Skeleton too.

  Migration guide: [Skeletons](https://github.com/envsemble/envUI/blob/main/docs/migration.md#skeletons).

- Avatar hues are named for their colors: `blue` is `powder`, `teal` `seafoam`, `green` `sage`, `amber` `butter`, `red` `blush`, `violet` `periwinkle`, `purple` `orchid` and `slate` `oat`, in `hue`, `avatarHues`, `AvatarHue` and `avatarHue`, and as the values of `data-hue`: `[data-hue='blue']`, `[data-hue='teal']`, `[data-hue='green']`, `[data-hue='amber']`, `[data-hue='red']`, `[data-hue='violet']`, `[data-hue='purple']` and `[data-hue='slate']` are `[data-hue='powder']`, `[data-hue='seafoam']`, `[data-hue='sage']`, `[data-hue='butter']`, `[data-hue='blush']`, `[data-hue='periwinkle']`, `[data-hue='orchid']` and `[data-hue='oat']`. A name keeps the hue it had, now under its new name.

  The tokens follow: `--env-color-avatar-bg-teal` and the others are `--env-color-avatar-bg-seafoam` and so on, with `--env-color-avatar-fg-{hue}` and `--env-color-avatar-figure-{hue}` beside them, and each hue, powder included, has tokens of its own. `--env-color-avatar-bg`, `--env-color-avatar-fg` and `--env-color-avatar-figure` stay, the powder hue's.

  To migrate, `v1-props` rewrites a literal `hue`, such as `<Avatar hue="teal">` to `hue="seafoam"`, and `v1-classes` the token names; rename `data-hue` values in your own CSS by hand. A fill you set on an old `--env-color-avatar-bg-{hue}` for a color of your own now sits under the hue's deep foreground, so set `--env-color-avatar-fg-{hue}` and `--env-color-avatar-figure-{hue}` beside it, to a color that keeps 4.5:1 on that fill. The ESLint plugin and the Stylelint config know the new token names.

- CounterBadge folds into Badge: a Badge with `count` is a compact count.
  - `<Badge count={12} />` shows a count, a number or short text such as 99+, in a compact round pill with tabular figures, in place of a label. It takes the tones and variants of any badge: neutral and soft by default, with the figures in the default text color, and `tone="accent" variant="solid"` for the filled count that needs attention. Its `aria-label`, such as 12 unread, is read in place of the number.
  - CounterBadge and `CounterBadgeProps` are gone, and so are 0.x's Counter and `CounterProps`, which 1.0.0-prerelease.0 renamed to them: `<CounterBadge value tone>` is `<Badge count tone>`, with `variant="solid"` in the accent tone. Bar's counts and Toast's count of hidden notices are Badges with `count`.
  - The part classes `env-counter-badge` and `env-counter-badge-label` are `.env-badge[data-count]` and `env-badge-count-label`, and the hooks a control sets for the counts inside it, `--env-counter-badge-fg`, `-bg` and `-border`, are `--env-badge-count-fg`, `-bg` and `-border`.
  - `v1-structure` rewrites CounterBadge and Counter into a Badge with `count`, and reports a `tone` that is an expression; `v1-names` renames `CounterBadgeProps` and `CounterProps` to `BadgeProps`, and `v1-classes` renames the classes and hooks. `envui/no-renamed-exports` reports Counter with what replaces it.

  Migration guide: [Folded components and patterns](https://github.com/envsemble/envUI/blob/main/docs/migration.md#folded-components-and-patterns).

- ColorPicker and ColorSwatch move to their own entry point, `@envsemble/envui/color`, rebuilt on React Aria's color hooks (`@react-aria/color`, `@react-stately/color` and `@react-aria/i18n`), which the application installs, as the setup guide lists; an application that never imports the entry never loads them. The main entry exports neither any more.
  - **ColorPicker** is compact: a saturation and brightness area, a hue slider, an alpha slider and field with `alpha`, a format menu and quiet fields for hex, RGB and HSL, each channel named by its letter beside its number, such as R, G and B, a copy button, the browser's eyedropper where it has one (`eyeDropper`), and preset `swatches`. `formats` chooses the formats and their order, and `copy` the copy button. `value` and `defaultValue` take a CSS color string, hex, `rgb()` or `hsl()`, or React Aria's `Color`; `onValueChange(value, color)` receives the string in `valueFormat`, `#rrggbb` by default, and the `Color`; `name` submits the string through a hidden input. `showLabel`, `description`, `error`, `disabled` and `readOnly` stay; `variant` is gone, and `ref` reaches the picker's root rather than the HEX field. Fields commit on Enter and as focus leaves, and the arrow keys step them.
  - **ColorPickerButton** is a compact button that shows a color as a swatch and its value, named after its label, and opens a ColorPicker in a popover.
  - **ColorSwatch** is a small rounded square with a checkerboard under a translucent color. `format` writes its value beside it, `label` a name, and `size="sm"` makes it smaller; alone, it is an image named by its color's description, such as dark purple. As the icon of an IconButton in its default variant, the button is a rounded square with no fill at rest, which shows on hover, focus and press.
  - EnvUIProvider's `messages.colorPicker` holds `format`, `formatButton`, `hex`, `rgb`, `hsl`, `hexField`, the channel letters `redShort` to `alphaShort`, `copy`, `eyeDropper`, `swatches` and `button`; `description`, `invalid`, `hexLabel`, `restored`, `hue`, `area` and `areaValue` are gone, as React Aria names the channels and the area in the provider's locale.
  - Parts: `env-color-picker-plane`, `env-color-picker-saturation`, `env-color-picker-saturation-slider`, `env-color-picker-saturation-thumb`, `env-color-picker-hue-control`, `env-color-picker-hue-thumb`, `env-color-picker-hue-track` and `env-color-picker-status` are gone. The area is `env-color-picker-area`, its thumb and the sliders' `env-color-picker-thumb`, the sliders `env-color-picker-slider` (`env-color-picker-hue`, `env-color-picker-alpha`) with `env-color-picker-track`, and the fields `env-color-picker-fields`; a swatch's color is `env-color-swatch-sample`.

  The `v1-props` and `v1-entries` codemods move the props and the imports.

  Migration guide: [Color picker and swatches](https://github.com/envsemble/envUI/blob/main/docs/migration.md#color-picker-and-swatches).

- ColorPicker's `formats` with two or more formats shows them at once, instead of limiting the format menu to them as in 1.0.0-prerelease.2: `formats={['hex', 'rgb', 'hsl']}` shows each format's fields on a row of its own, in that order, with a copy button of its own, all editing the same color, their letters and numbers lined up from row to row. Each row is a group named after its format, and its copy button takes the new `messages.colorPicker.copyFormat`, such as Copy color as RGB. With one format, or without `formats`, the picker shows one format at a time as before, and the format menu stays the default. ColorPickerButton passes `formats` to its picker too.

  To migrate, check each ColorPicker and ColorPickerButton with two or more `formats`: keep them to show those formats together, or remove `formats` to keep one format at a time with the menu, which then offers hex, RGB and HSL. A menu of only some formats is gone; to offer one format, pass it alone, such as `formats={['hex']}`.

- Any single element can take colors of its own, Material's way. envUI's own colors don't change.
  - **Component color properties.** Each component has public color properties on its root, named `--env-<component>-<role>`, after Material's component tokens: container, content, outline and icon where they apply, selected and selected-content for what is chosen, current or on, and indicator for a field's focused edge and a slider's fill, such as `--env-button-container`, `--env-list-item-selected` or `--env-text-field-indicator`. Set them on one instance through `style` or a selector that matches it: they are registered so they don't inherit, so one set on a wrapper colors nothing inside it. Button, IconButton and a toolbar's toggles, Card, Surface, Badge, Alert, Avatar, Tooltip, Toast, List rows, Menu items, the items of Bar, Rail and Drawer, Tabs, SegmentedControl, TextField, Textarea, Select, Checkbox, Radio, Switch, Slider and Combobox's chips have them. They are public and versioned: `docs/generated/parts.json` lists them with the parts, with what each colors, the manifest and the MCP server's `get_component` return them, and each component's page names them under Anatomy.
  - **States follow the colors you set.** With no color property set, every component paints its designed colors in every state, as before. Once its container or content is set, hover, keyboard focus and press lay the content color over the container at the new tokens `--env-state-hover-opacity`, `--env-state-focus-opacity` and `--env-state-pressed-opacity`, so it keeps working states.
  - **A nested Theme still recolors an area:** override the semantic `--env-color-*` tokens on it, with their hover and pressed values. [Customize and extend](docs/customizing.md) describes both ways.
  - **Renamed component tokens.** `--env-list-item-fill` is `--env-list-item-container`; `--env-alert-tint`, `--env-alert-edge` and `--env-alert-tone` are `--env-alert-container`, `--env-alert-outline` and `--env-alert-icon`; `--env-toast-fill` and `--env-toast-edge` are `--env-toast-container` and `--env-toast-outline`. The old tokens inherited and the color properties don't: a token set on a wrapper reached the component inside it, and its color property set there colors nothing, so set it on the component itself. `envui-codemods v1-classes` renames them, also where a renamed class gives one of the old names, and reports each declaration in a rule whose selector doesn't end at the component, such as `.my-alert` rather than `.my-alert .env-alert`; a style object or `setProperty` call on a wrapper element it can't tell, and the migration guide says so.
  - **Removed component tokens.** A toast's hover and pressed tokens, `--env-toast-fill-hover` and `--env-toast-fill-pressed`, are gone: set `--env-toast-container`, and the dismiss button's hover and press become layers of the toast's text color. `v1-classes` reports them.
  - **`--env-badge-outline` changed meaning.** In prerelease.1 it was a private border shorthand, such as `0.0625rem solid <color>`; now it is the badge's public outline color. Write `--env-badge-outline: <color>`: a shorthand is an invalid color, and the badge draws no edge.

  Migration guide: [Color properties and state layers](https://github.com/envsemble/envUI/blob/main/docs/migration.md#color-properties-and-state-layers).

- envUI's components lay out their own parts with Row, Column and Grid instead of flex and grid rules of their own, so the parts that arrange others carry `data-env-layout` (and dev mode names them). Their part classes, state attributes and look are unchanged: what was a grid is a Grid, a flex row or column a Row or Column, and a part's own class still overrides the primitive's rules.

  Row and Column zero the block margins of their direct children (and Row the inline ones too), so content of yours placed directly in such a part loses its default margins, such as a `<p>` passed to List.Item, Message's actions, Alert's `action`, Card's header or Tabs. Give it a class with the margin you want, or wrap it. Parts that were grids, such as Message, Popover and Field, keep their children's margins. Migration guide: [Layout primitives](https://github.com/envsemble/envUI/blob/main/docs/migration.md#layout-primitives).
  - Feedback and floating surfaces: Alert, Dialog's header, Meter, Progress, Popover, HoverCard, CommandPalette, the popups of Menu, Select, Combobox, DatePicker, MonthPicker and TimePicker.
  - Content: Card's header, CodeBlock's heading, CalendarHeatmap, List, Message and MessageList.
  - Form controls: Field and its error, Calendar, the month grid, the panes, time column and actions of DatePicker, MonthPicker and TimePicker, DropZone, Composer, MarkdownEditor's write pane, RadioGroup and Slider's heading.
  - Navigation and actions: Breadcrumbs, DocumentTabs' bar and strip, Menubar, Pager's row, Pagination, Tabs, Toolbar and its groups, and PanelDock's dock, panels, tab strip and header parts. A Toolbar or Toolbar.Group given `render`, such as a ButtonGroup, is now laid out by that element's own rules, so a ButtonGroup keeps its connected spacing.

- Drawer, the panel that slides in over the page, is Sheet, after Material's side and bottom sheets; the name Drawer is the navigation drawer's. Sheet takes Drawer's props, and `side="bottom"` for a bottom sheet, as wide as the window up to 40 rem and as tall as its content, with rounded top corners and a swipe down to close.
  - Its widths follow the window classes of the `env-window` container instead of the viewport: a `md` side sheet takes the whole width of a compact window, below 37.5 rem, and a `lg` one of a compact or medium window, below 52.5 rem.
  - The part classes `env-drawer-popup`, `env-drawer-viewport` and `env-drawer-backdrop` are `env-sheet-popup`, `env-sheet-viewport` and `env-sheet-backdrop`, with the same state attributes, `data-side`, `data-width`, `data-starting-style`, `data-ending-style` and `data-swiping`.
  - `v1-structure` turns a 0.x `<Dialog placement="right">` into a Sheet. 0.x had no Drawer, and the name is the navigation drawer's now, so no codemod renames one: rename `Drawer` and `DrawerProps` from the prerelease to `Sheet` and `SheetProps`, and the `env-drawer-*` classes to `env-sheet-*`, by hand. `v1-structure` reports a Drawer without `destinations`, and `v1-classes` the classes.

  Migration guide: [Overlays and feedback](https://github.com/envsemble/envUI/blob/main/docs/migration.md#overlays-and-feedback).

- EmptyState is a pattern now, not a component: it carries no behavior, and its parts are envUI's own.
  - EmptyState and `EmptyStateProps` are gone. The empty states pattern, `docs/patterns/empty-states.md`, builds one from a Column with an icon, a Text heading, a Text sentence and a Button: at the start of a card or under a list's toolbar, or centred with a larger icon where it takes a region's place. Its notes keep what EmptyState took care of: the heading's level in the page's outline, which `headingLevel` set, and the alert role of a failure, which `tone="danger"` set.
  - The part classes `env-empty-state` and `env-empty-state-description` go, with `data-tone` and `data-align`. CodeDiff shows a failure to load with its own parts, `env-code-diff-failed` and `env-code-diff-failed-icon`, as an alert. The `empty-state` page opens the pattern.
  - `v1-names` reports EmptyState where it is used, and `v1-classes` its classes and 0.x's `env-empty-copy`; no codemod rewrites them. `envui/no-renamed-exports` reports them with the pattern to use instead.

  Migration guide: [Folded components and patterns](https://github.com/envsemble/envUI/blob/main/docs/migration.md#folded-components-and-patterns).

- Card's feature layout is built from envUI's components now: Card keeps its surface and its parts, and a feature card is a Card holding envUI's own components.
  - Card's `layout` and `icon` props are gone, with the `data-layout` attribute, `[data-layout='feature']`, `[data-layout='stack']` and the part classes `env-card-layout` and `env-card-icon`. A card with actions is `.env-card[data-actions]`, and a card's title is an `h3` by default whatever it holds.

- Part names are public; component tokens are private.

### Minor Changes

- Accordion, a list of sections on Base UI's Accordion: `Accordion.Root` holds `Accordion.Item`s, each a heading that shows and hides its panel, separated by hairlines across the full width, a line under every item. ## 1.0.0-prerelease.0 — 2026-10-18

The first prerelease of envUI 1.0, published under the `prerelease` dist-tag; 1.0.0 follows after further changes. It brings contrast-safe themes built from design tokens, established component names, AppShell and its parts, page templates, new pickers for times and months, and documentation and tooling for people and agents alike. It breaks code written for 0.x: `@envsemble/envui-codemods` makes most of the changes, and the [migration guide](https://github.com/envsemble/envUI/blob/main/docs/migration.md) covers the rest.

### Major Changes

- Alert and EmptyState say `danger` for the status that was `error`.
  - Alert's `tone` is `info`, `success`, `warning` or `danger`, and `AlertTone` follows. Its dismiss button is a CloseButton, named Dismiss through `messages.alert.dismiss`, and Alert stays a server component.
  - EmptyState's `tone` is `neutral` or `danger`. Its modifier classes are attributes: `env-empty-state-error` is `[data-tone='danger']` and `env-empty-state-center` is `[data-align='center']`; `env-empty-copy` is `env-empty-state-description`.

  Migrate with the codemods: `envui-codemods v1-props` maps `tone="error"` to `tone="danger"` and reports an expression; `v1-classes` rewrites the classes.

  Migration guide: [Overlays and feedback](https://github.com/envsemble/envUI/blob/main/docs/migration.md#overlays-and-feedback).

- AnimatedNumber's `format`, the function that writes its value, is `formatValue`, as on Slider and CalendarHeatmap.

  Migrate with the codemods: `envui-codemods v1-props` renames `format` to `formatValue`.

  Migration guide: [Content and display](https://github.com/envsemble/envUI/blob/main/docs/migration.md#content-and-display).

- AppShell is made of parts: `AppShell.Root` lays out `AppShell.SkipLinks`, `AppShell.Header`, `AppShell.Main`, an `AppShell.Aside` and the sidebars in a grid that follows the text direction, and keeps the sidebars' state per side. The sidebars are `Sidebar.Root` with `Sidebar.Header`, `Content`, `Group`, `Footer` and `Handle`, opened and closed by `SidebarTrigger` and read with `useSidebar`; `Sidebar.Provider` gives a sidebar the same state without the frame. A sidebar collapses to a rail of icons (`collapsible="rail"`) or out of view (`offcanvas`), its rail opens over the content on hover and focus (`peek`), it docks from `dockAt` up, resizes with its handle, and below the frame's breakpoint (48 rem by default, 40 rem before) its content opens in a drawer from its side. Expanding and collapsing never remount its content.

  `persist` keeps both sidebars' docked preference and width (in rem) in localStorage, or in a cookie that the server reads with `readAppShellCookie` for `initialState`, so a server-rendered frame paints as it was left. `shortcut="mod+b"` toggles a sidebar; it is off by default. The frame publishes `--env-frame-header-block-size` and `--env-frame-sticky-top`, which replace `--env-app-topbar-block-size` and `--env-app-sticky-top`, and `useAppShell().getStickyTop()` reads the second; WindowFrame.Root publishes the same, and `useAppShell` works inside it. `titleBar` makes the header the window's title bar, on WindowFrame's title bar internals, with Main scrolling below it. `closeNarrowSidebar` is `useSidebar().dismiss()`. AppShellSkeleton is removed: the frame's parts with the new `NavList.Skeleton` inside a LoadingState are its loading state. Under a coarse pointer the trigger is 44 px and the rail grows with it.

  Migration guide: [The app frame](https://github.com/envsemble/envUI/blob/main/docs/migration.md#the-app-frame).

- An app scale: `Theme` and `ThemePreferenceProvider` take `scale`, `comfortable` (the default, today's sizes) or `compact`, about 0.8 of them with type one step smaller, for desktop productivity apps. Left out, a Theme takes the scale of the Theme around it. Theme writes it to `data-env-scale` on every boundary, nested ones and those around popups included, and `useTheme()` returns `{ theme, contrast, scale }`. `createThemeBootstrapScript({ scale: 'compact' })` puts the compact scale on the root before the first paint. Outside any Theme, a `ThemePreferenceProvider` without a `scale` or a `contrast` gives its boundary the scale and contrast the page set on the root, so the application matches the page and other libraries' portals; one that unmounts, or whose `applyToDocument` turns false, removes the scale and contrast it wrote on the root, unless the page wrote over them or another provider holds them. Use one scale per app or window, and another only on a Theme around a whole region.

  Every size is a token, with a value per scale: `--env-control-height-xs`, `-sm`, `-md` and `-lg`, `--env-row-height`, the row densities' `--env-row-padding-block-*`, `--env-control-gap`, `--env-font-size-caption` and `--env-font-size-label`, `--env-icon-size-sm`, `-md` and `-lg`, `--env-radius-lg`, `--env-field-floating-height`, `--env-row-content-height` and a tree row's paddings, `--env-tree-row-padding-block-sm`, `-md` and `-lg`, are new, and the spacing, type, corner, top bar and title bar tokens take their compact values in the compact scale. Icons keep a 1 rem floor, and borders and focus rings keep their widths. The type roles `--env-type-h1`, `--env-type-h2`, `--env-type-body` and `--env-type-body-small` are tokens now, with a custom property for each part, such as `--env-type-body-font-size`.

  Removed custom properties: `--control-height-small` and `--icon-button-size`, which `--env-control-height` replaces, `--control-height-compact`, which `--env-control-height-sm` replaces, and the `--scale` multiplier, which components no longer read. `--env-control-height` is the height of a control that sets no size; a container can set it to another control height for what it holds, as table cells do with `--env-control-height-sm`.

  Under a coarse pointer, `@media (pointer: coarse)`, controls grow to at least 2.75 rem in either scale: buttons and icon buttons, tall and wide, fields, Select, the rails of SegmentedControl and Tabs, ButtonGroup, Pagination, menubar triggers, AppShell's sidebar toggle and collapsed sidebar, a toast's dismiss button, AvatarButton, sortable table headers, and the close buttons of PanelDock chips and DocumentTabs. The control tokens keep their values; an application's own control takes `max(var(--env-control-height), var(--env-control-height-touch))` under the same query. A link in running text, a breadcrumb link, a combobox chip's remove button, an interactive AvatarGroup's avatars and a Switch's track stay smaller and rely on WCAG 2.5.8's spacing exception. The controls of a row still match, and a control's own box is its hit area, so a press always reaches the control it lands on, whatever the layout around it. Segments, tabs and the actions inside fields take presses across their control's height, within it. Rows, navigation items and table rows with an action grow to at least 2.75 rem too, and the top bar and the title bar to 3.25 rem.

  Migration guide: [Scale and density](https://github.com/envsemble/envUI/blob/main/docs/migration.md#scale-and-density).

  - **Removed:** `density` on Select, Combobox, DatePicker, Surface, Menu.Root, ContextMenu and Menubar.Menu; `compact` on TextField and SearchField; `size` on NavList.Item; the `standard` and `compact` sizes of Tabs, SegmentedControl, Pagination and CopyButton, which are `md` or `lg` and `sm`. DropZone's `compact` is `size="sm"`. For a compact app or region, set `scale="compact"` on its Theme; for a small control, set `size="sm"`.
  - **Rows match:** buttons, icon buttons and fields in table cells take the small control height at every density, so a row with an action is no taller than it needs to be. Title bars, panel headers, message actions and the date picker's popup hold small controls.

  Migration guide: [Scale and density](https://github.com/envsemble/envUI/blob/main/docs/migration.md#scale-and-density).

- envUI's CSS moves into cascade layers, and every token takes the `--env-` prefix.
  - **Cascade layers.** Every rule of `styles.css` is in a layer of `env`: `env.reset`, `env.tokens`, `env.base`, `env.components` and `env.utilities`, in that order. An application's CSS outside cascade layers overrides envUI's whatever its specificity, so selectors and `!important` that only out-weighed envUI's rules can go. An application puts its resets and element styles in a layer before `env` and its own layers after it, declared once, such as `@layer reset, env, app;`: an element rule outside layers would restyle envUI's components too. The font face stays outside layers.
  - **The `--env-` prefix.** Every token is a custom property with the prefix: `--space-4` is `--env-space-4` and `--color-fg-muted` is `--env-color-fg-muted`, in Tokens.css, the token reference, the manifest and the MCP server. The application hooks take it too: `--env-line-height-body`, `--env-avatar-group-ring` and the pill corner `--env-radius-full`.
  - **The 0.7 aliases are removed.** `--color-text-muted`, `--color-row`, `--color-checkbox` and the other 0.7 names that were aliases of the semantic roles are gone; use the role that replaces each. The list item's per-theme fill and the avatar's fixed blues are component tokens now: `--env-color-list-item-bg` with `-hover` and `-pressed`, and `--env-color-avatar-bg`, `-fg` and `-figure`. `--md-sys-shape-corner-*` is retired for one radius scale, `--env-radius-{none|xs|sm|md|lg|xl|full}`, with `--env-radius-surface` and the row radii as its roles; `--radius-standard` is `--env-radius-sm` and `--radius-large` `--env-radius-lg`.
  - **Consistent color names.** A tone's edges grow from `border-{tone}-muted`, an alert's faint edge, through `border-{tone}`, an outlined badge's translucent edge, to the solid `border-accent-emphasis` and `border-danger-emphasis`, the edges of a focused and an invalid field, which were `border-accent` and `border-danger`. `border-translucent` is `border-media` and `bg-page-muted` is `bg-inset`, named for their roles, and the tones' state layers gain a resting `bg-{tone}-subtle`.
  - **Forced colors.** Under `forced-colors: active`, such as the system's contrast themes, selected, chosen, current, highlighted, checked, focused, invalid and unavailable states take system colors where a fill or shadow carried them, so they stay visible, and swatches, the color picker and calendar heatmaps keep their colors.
  - **Motion** lives in each component's style sheet; it is unchanged, with fades always and movement only without a reduced-motion preference.

  To migrate, run `npx @envsemble/envui-codemods v1-classes src`: it rewrites the old custom properties in style sheets and scripts, declared or read, to their 1.0 names, the 0.7 aliases straight to the tokens that replace them, and reports `--color-white`, `--color-canvas-dark` and the removed names with what to use instead. The migration guide lists every name. The ESLint plugin and the Stylelint config suggest the prefixed tokens.

  Migration guide: [Cascade layers](https://github.com/envsemble/envUI/blob/main/docs/migration.md#cascade-layers) and [Tokens](https://github.com/envsemble/envUI/blob/main/docs/migration.md#tokens).

- Dialog's side panel is a new component, Drawer, and Dialog takes `width`.
  - Drawer is a full-height panel at the `start` or `end` edge of the window (`side`, default `end`), which follows the text direction: it slides in from its edge, and closes with a swipe toward it on a touch screen. It takes Dialog's `title`, `description`, `actions`, `trigger`, `modal`, `disablePointerDismissal`, `pending`, `initialFocus` and `finalFocus`, and adds `aria-label` for a drawer without a visible title, `closeButton`, and `width`: `md` (24 rem, the default), `lg` (44 rem) or any CSS length. Its close button is a CloseButton. Opened by keyboard or mouse, focus starts on the first element inside that takes Tab; opened by touch, or with nothing inside that takes focus, on the drawer itself, so a field inside doesn't open the on-screen keyboard.
  - Dialog's `placement` is `center` or `top`; `placement="right"` is `<Drawer side="end">`. Dialog's `size` is `width`: `standard` is `md`, the default, and `wide` is `lg`.
  - `onOpenChange` of Dialog and Drawer receives the reason as its second argument, such as `escape-key` or `close-press`; `initialFocus` and `finalFocus` also take a function of the interaction. Dialog and DialogClose take `ref` as a prop.
  - The dialog's surface class `env-modal-pane` is `env-dialog-popup`; a drawer's is `env-drawer-popup`, and both carry `env-dialog-surface`.

  Migrate with the codemods: `envui-codemods v1-structure` turns a `<Dialog placement="right">` into a `<Drawer side="end">`, with its `size` as `width`, and reports a `placement` that is an expression; `v1-props` turns Dialog's `size` into `width`; `v1-classes` renames `env-modal-pane`.

  Migration guide: [Overlays and feedback](https://github.com/envsemble/envUI/blob/main/docs/migration.md#overlays-and-feedback).

- MarkdownEditor and RichTextEditor share their toolbar, their link dialog and their status, and take their words from EnvUIProvider's `messages` (`markdownEditor`, `richText`, `editor` for the formatting commands and `linkDialog`):

Its class is `env-editor-toolbar`, where it was `env-markdown-toolbar`, and the status line's is `env-editor-status`, where it was `env-markdown-editor-status`.

  RichTextEditor takes the field vocabulary and the field's look, in the experimental `./rich-text` entry:

  - Task items in the editor are envUI checkboxes beside their text, named by it.

- Fields and popups have one anatomy each, at the sizes of the app's scale:

- Colors now come from a primitive palette with contrast built in, through semantic color tokens, and every theme passes the contrast gate with no exceptions, including two new high-contrast themes.
  - **Palette.** Ten hues (neutral, blue, slate, steel, green, teal, amber, red, violet, purple) seeded from the previous colors, on one grade scale from 0 (white) to 100 (black). Each grade is a band of WCAG luminance, so colors 40, 50 and 70 grades apart have at least 3:1, 4.5:1 and 7:1, in any hue. The palette is internal.
  - **Semantic tokens.** `--env-color-{bg|fg|border}-{role}-{emphasis}[-{state}]`, for example `--env-color-bg-default`, `--env-color-fg-muted`, `--env-color-border-default` and `--env-color-bg-brand-emphasis-hover`. Hover and pressed colors are tokens of their own instead of a runtime lightness shift. The 0.7 names, such as `--color-text-muted`, are replaced by these roles; the synonyms of muted text (quiet, icon, field label, hint, placeholder, row detail) now share one value.
  - **High contrast.** Set `contrast="high"` on a Theme, or let the system's `prefers-contrast: more` apply it, for text at 7:1 and boundaries, indicators and focus rings at 4.5:1. The translucent tone colors, such as the edges of outlined badges and alerts, an alert dismiss button's hover and the slider halo, follow the high-contrast tone too. `contrast="standard"` keeps the standard colors.
  - **Elevation.** `--env-elevation-{0…3}-shadow` and `--env-elevation-{0…3}-border`. Every popup takes a shadow and a hairline edge: menus, Select lists, popovers, tooltips and toasts at level 2, so they stand out from a page of their own color, dialogs and the command palette at level 3. Tooltips and toasts take an edge that follows their fill, `--env-color-border-{neutral|success|info|danger}-strong`: in light the fill a step darker, so a dark tooltip or toast on a light page has no light halo, and in dark the popup edge. The edge is the boundary in high contrast and under forced colors.
  - **Selection and states.** The selection can't be mistaken for another item at rest or under the pointer in any theme: a blue tint in light, a blue-gray in dark. Navigation items hover in the blue-gray again in light, deeper than the selection as in 0.7, and in a gray at high contrast; destructive buttons lighten on hover, and success toasts are teal again. In dark, checked checkboxes, switches, sliders, meters and spinners take the soft blue of the radio with dark marks. ## 0.5.0 — 2026-10-14

Components for document-centred desktop applications and data-heavy dashboards: a file tree, editor tabs, quick open, context menus and a resizable sidebar; sortable, resizable tables, key figures, a heatmap, conversation messages and split views; with badges, notices and other everyday pieces.

### Breaking changes

- A document root themed through `ThemePreferenceProvider` or the bootstrap script keeps the browser's font size, so 1 rem is 16 px by default instead of 15 px and envUI renders at its designed size, no longer a sixteenth smaller. Migration: an application's own rem-based CSS on such a root grows by about 7%; multiply its rem values by 0.9375 to keep their earlier size. The document body takes envUI's body type at zero specificity, so an application's own `body` rule outside cascade layers styles the body element and the text that inherits from it outside envUI's themed boundaries; paragraphs and headings take envUI's type anywhere under a themed root, and envUI's type, with a unitless line height, applies inside the boundaries: the provider's boundary, a `Theme` and envUI's popups. A rule inside `@layer` loses to envUI's unlayered style sheet. Migration: an application that set its typeface, font size or line height with a `body` rule no longer reaches its content inside the provider that way; set envUI's font tokens, such as `--font-family`, `--font-size-body` and `--line-height-body`, for `.env-theme` in a style sheet that loads after envUI's, or style that content directly.

## 0.4.0 — 2026-10-11

Clearer contrast in both themes, more ways to show loading, and refinements from reviewing the catalogue and an application built with it.

### Changed

- Fills are translucent layers of the text color instead of fixed grays, so they stay distinct on panes, rows, cards and dialogs while keeping their tone on the canvas.
  - `--color-secondary-action`, `--color-chip`, `--color-switch-off`, `--color-skeleton-base` and meter tracks use the new `--color-fill` (6% in light, 12.5% in dark), with `--color-fill-hover` and `--color-fill-pressed`.
  - Secondary buttons in dialogs and side panels, tab rails on panes, and chips and switches on rows no longer blend into their surface.
  - The 0.2.0 rule that shifted secondary buttons on row fills is replaced by the translucent fill.
- Hover and press on cards, rows, select options, radio rows and menu items shift 6 and 10 points of lightness, up from 2 and 4.
- A floated field label hides only the outline behind it, so it no longer shows the field color as a box above the outline on panes and dialogs.
- `CodeBlock`'s heading follows the code theme, so its copy action uses that theme's colors and stays visible on the dark code background in a light application.
- Inactive tabs show translucent hover and press layers, visible on their rail in both themes.
- Icon-only text buttons, such as a field's clear action, show the same state layers instead of only a faint color change. Inside a field they use its quiet icon color rather than the link blue.
- Press feedback reaches every control:
  - Select triggers, the sidebar toggle and toast dismiss settle like buttons.
  - Direction links and radio rows settle like clickable cards.
  - Checkboxes, radios and switches shrink slightly whether the control or its label is pressed.
- Rows, radio rows, select options and menu items keep 1.5 rem inline padding (`--row-padding-inline`), up from 1 rem, so text clears the large corners on single and connected rows alike. Surfaces keep at least 1.25 rem padding.
- `AppShell`'s expanded sidebar fits its widest content (the navigation or the context beside the toggle) between 12 and 20 rem instead of a fixed 16 rem, and stores the width with `storageKey` so `AppShellSkeleton` matches it. The collapsed sidebar is one control plus its insets wide, so the toggle lines up with the navigation icons.
- The `OrganizationMenu` trigger is a secondary `Button` with the up and down arrows, instead of its own style.
- The `AppShell` sidebar toggle becomes a secondary icon button while its toggle icon shows, instead of using the navigation hover tint; at rest it remains the brand mark.
- `Avatar` initials use the avatar blue of the default person picture (`--color-avatar`, `--color-on-avatar`).
- Toasts glide to their new place when another notice arrives or leaves. The hidden-notice count of the top-center placement sits below the stack, centered.
- A Select's open list is a raised popup in its own color (`--color-popup`) with a hairline border (`--color-popup-border`). It no longer blends with dialogs and panes of the same tone. Options show only hover, press and selection; in dark, the selected option has a blue tint.

### Added

- `AvatarButton`: a person's avatar as a button, typically the account menu trigger. A halo shows hover, press and an open menu, and the tooltip shows the name and an optional detail such as the e-mail address.
- `LoadingBar`: page-level progress that appears after a short delay, creeps forward while work continues, then completes and fades out. `AppShell`'s `loading` prop shows it along the topbar's bottom edge.
- `Spinner`: work of unknown length in a small area, in small, standard and large sizes.
- `pending` on `Button` and `IconButton`: a spinner replaces the content at the same size, and the button reports busy and ignores activation.
- `showLabel` on text fields: compact fields can show a label that rests inside and floats into the outline, without changing their height.
- `--color-state-layer-hover`, `--color-state-layer-pressed` and `--row-padding-inline` tokens.
- `ConfirmButton`: an action that takes effect at once is confirmed in place. The first press arms the button and names the consequence, and the second press runs it. A double click only arms it, and the arming ends after a few seconds, when focus leaves and on Escape.
- `AnimatedNumber`: a count rolls up as it grows and down as it shrinks, and fades with reduced motion.
- `OrganizationMenu` organizations accept a `detail`, such as the person's role, shown muted after the name.
- `headingLevel` on `EmptyState`, for an empty or error state that is the whole page.
- `variant` on `Select`: secondary (default) is the filled pill, and outlined a bordered pill for panes, dialogs, rows and toolbars.

### Documentation

- The loading page covers page progress, spinners, pending buttons and placeholders, with guidance on when to use each.
- The catalogue's icon search uses `SearchField`, and the compact field examples show the floating label and end action.
- The dialogs page shows dialogs with forms (fields and validation, a choice, a typed confirmation), and its pending example uses a pending button.
- The buttons page asks labels to say what will happen, with examples of a live count and confirming in place. A new page covers animated numbers.

The application frame and menus, so products share one sidebar and navigation.

  - controls settle slightly while pressed;

  - menus, select options and tooltips grow from their trigger;

## 0.2.0 — 2026-10-11

Foundations found missing while adopting envUI in the first application to use it.

### Breaking changes

- The content and rich-text dependencies (Shiki, react-markdown, remark-gfm, marked and Tiptap) are optional peer dependencies. Applications that import `@envsemble/envui/content` or `@envsemble/envui/rich-text` install them; applications using only the main entry no longer download them.
- Secondary buttons on row fills (grouped rows, row-tone cards and card action strips) shift from the fill by the control lightness rule instead of using the row color, so they stay visible.
- Toast messages wrap to three lines within 28 rem instead of truncating to one line.

### Added

- `ThemePreferenceProvider`, `useThemePreference` and `ThemeToggle`: a stored light, dark or system preference that themes the document root, so the page background, native controls and other libraries' portals match.
- `createThemeBootstrapScript` from the new `@envsemble/envui/theme-bootstrap` entry: an inline startup script that applies the saved theme before the first paint.
- `LinkProvider`: Button, Link, NavigationItem, Card and DirectionLink destinations render through the application's router link, without a router dependency in envUI.
- `Input` `startIcon`, `endAction` and `compact`; compact fields match the button height for toolbars.
- `SearchField`: a compact search input with a search icon and a clear action; Escape also clears.
- `Dialog` `pending`: Escape, outside presses and the built-in close button cannot dismiss the dialog while work is in progress.
- `EmptyState` `tone="error"` for content that failed to load.
- `Text` `variant="display"` for page heroes.
- `Tooltip`, `Avatar` (with the default person picture or initials as fallback, and `getInitials`), `Meter` and `Progress`.

### Documentation

- New pages for tooltips, avatars, and meters and progress; theme preference, router links and optional dependencies in setup; source mode and checks while linked in local development.

## 0.1.0 — 2026-10-10

The first published release of envUI: a private React 19 component library with light and dark themes, an offline catalogue and packaged agent skills.

### Foundations

- `Theme` and `useTheme` for scoped light and dark themes. The design tokens give each component family its own color roles: surfaces, rows, buttons, navigation, form controls and feedback. Hover and pressed shades are derived from each base color.
- Local Inter, the official Material Symbols Rounded icons as React wrappers, and envUI branding (`EnvUILogo`, `BrandLogo`, lockups and favicons).
- Responsive layouts, and a 2.75 rem minimum touch target on coarse pointers with no consumer overrides.
- Layout and text: `Stack`, `ActionGroup` (both with semantic tags), token-based `Text`, and `Surface` for backgrounds, padding and corners.

### Actions and navigation

- `Button`:
  - variants, including a borderless `text` variant;
  - native links through `href`;
  - one shared control icon size.
- `IconButton`.
- `Link`: an inline link built on `Button`, underlined by default.
- `ButtonGroup`: connected horizontal or vertical button rows.
- `NavigationItem`:
  - selected and unselected icon variants;
  - `compact` labels;
  - `iconOnly` for collapsed sidebars.
- `DirectionLink` and `DirectionLinks`: previous/next destinations that wrap on narrow screens.
- `Tabs`: keyboard selection, animated panels, and `renderList` to place the tab list inside other layouts.

### Content

- `Card` covers plain, interactive and action-strip cards. `ClickableCard` and `ActionCard` remain as wrappers for compatibility.
- `FeatureCard`, `GroupedRows`/`Row` with connected corners, `DisclosureNote` and `InfoChip`.

### Forms

- `Input` and `Textarea` come in two appearances:
  - outlined, with floating labels;
  - plain, with an underline.
- They share labels, hints and errors. Validation shows as a red border, or a red underline on plain fields. Focus shows as a single blue border.
- `Textarea` sizes itself to its content, scrolls when fixed, and has a subtle full-width resize edge.
- `Select`, `Checkbox`, `Switch`, `Radio` and `RadioGroup`.
- `ColorPicker`: a color area, a hue slider and a HEX field.
- Form controls reset with their native form.

### Feedback

- `Dialog` and `DialogClose`.
- Managed toasts through `ToastProvider` and `useToast`:
  - top-center and bottom-right placements;
  - the newest notices stay visible, and older ones hide behind a count;
  - explicit durations, including `Infinity`;
  - timers pause while hidden and while focused.
- Independent manual `Toast`.
- `EmptyState`, `Skeleton` and `LoadingState`.

### Optional entries

- `@envsemble/envui/content`:
  - `Code` and `CodeBlock`, with lazy Shiki highlighting in the dark code theme in both app themes; `CodeBlock` accepts an explicit theme;
  - `Markdown`, with CommonMark plus tables, task lists, strikethrough, automatic links and footnotes, envUI prose and application-owned links;
  - `MarkdownEditor`, with Write/Preview, formatting, shared undo/redo and link insertion through an application picker.
- `@envsemble/envui/rich-text`: `RichTextEditor`, the read-only `RichText` and `createRichTextExtensions`.
  - Built on Tiptap, with Markdown values and configurable reference lookup.
  - Includes slash commands, with uploads and navigation handled by the application.
- Content and rich text are separate entry points, so applications that use only the basic components don't load parsing or highlighting code.

### Documentation

- An offline catalogue (`envUI.html`), built from the library's own components, is attached to each release.
- The packaged `envui-use` and `envui-migrate` agent skills.
